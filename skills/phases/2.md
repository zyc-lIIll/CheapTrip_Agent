# 阶段2：大局规划（划分 part + 游玩大方向 + 全程总览）

本阶段目标：让客户**先拥有整体大致印象并认可大方向**，细节留到阶段3逐 part 确定。

**划分 part 不靠想象，靠数据支撑**：攻略搜索 → 全部 geocode → 几何聚类（cluster_pois，确定性）→ 交通要素查证（route_check + 地铁/市区口径）→ 汇总输出 part 划分表。按以下九步走：

1. **搜成形攻略**：搜别人玩这片区域的成行攻略（如 `{目的地} 攻略 路线`、`{目的地} X天 行程`、`{目的地} 怎么玩`），再搜一些出名景点和重要枢纽（高铁站/机场名），交叉看几篇。**小红书真实笔记优先用 `search_xhs`**（环境未启用则用 search_web，但小红书内容需自行甄别来源），成形路线/避坑经验在评论区尤其多
2. **先做大白判断**：调聚类工具前，先从攻略+常识列出预期——**预期有几个交通便利区、大致在哪**（写明依据，如「陕北攻略里出现延安、榆林两市 → 预期至少 2 个交通便利区，中心大致在延安市区、榆林市区」）。这个预期决定了下一步的 `anchors` 和 `min_regions`
3. **候选点全部 geocode**：攻略中出现的候选景点 + 枢纽 + 预期区中心（市区），逐个 `geocode` 拿坐标（先查知识库 `skills/knowledge/`，有记录直接用）
4. **几何聚类**：调 `cluster_pois`，传入全部候选点 + `anchors`（预期区中心坐标）+ `min_regions`（预期最少区数）。**零散景点当不了桥**：两个市不会被中间一个景点并成一个区；结果不符预期时调整 anchors/min_regions 重调，不要硬掰结果
5. **交通要素查证**：
   - `route_check` 抽查（打车口径）：散点到区核心 ≤90min 才算可当天往返的辐射景点；区内最远两点 ≤30min 才算「打车方便」
   - 每个城市搜「{城市} 地铁」「{城市} 共享单车」：有地铁 → 核心范围扩大到地铁覆盖（沿线景点可并入）；无地铁 → 靠 route_check 验证
   - 搜「{城市} 市区 景点」对照网上口径，修正「算不算市区」的争议
6. **输出 part 划分表**：每个 part 列「交通便利区（核心范围）+ 枢纽（高铁站/机场及其位置形态）+ 辐射景点及归属」。**多归属点不让客户选**：按攻略归一个 part，展示时提一嘴「介于X与Y之间」即可
7. **向用户展示并请点评**：part 划分表 + 游玩大方向文字图 `出发地 → part A(X天) → part B(X天) → 返程`（含 part 间交通方式与大致耗时）；请客户对划分、顺序、大方向提意见。划分不合理 → 带先验重调聚类后再出表
8. **写会话记忆**：客户认可后 `update_notes`，按 part 结构化模板记录（见总则「会话记忆」）
9. **画全程总览图**：geocode 各交通便利区中心与出发地/目的地，调 `generate_overview_map`（全部 part + 辐射景点 + 大交通连线），路径告知用户

地图技能详见 `skills/map.md`；攻略与景点搜索策略详见 `skills/discovery.md`。

**本阶段完成**：part 划分与大方向经客户确认，全程总览图已生成。

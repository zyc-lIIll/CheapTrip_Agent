# 酒店搜索技能

## 搜索平台

在去哪儿旅行、智行火车票、携程旅行、大众点评等平台多平台寻找。以各平台上相同酒店评价的数量为权重加权打分选择最优。

## 真实评论查证（search_hotel_reviews）

**先筛后爬，爬是为了确认，不是用来筛选。** 流程严格如下：

1. **先按本技能标准（多平台搜索 + 评分门槛 + 品牌优先级）筛出 1 家主推 + 1 家备选**——筛选用 `search_web`，这一步不碰爬虫
2. 候选定稿后才爬：`search_web` 搜「site:hotels.ctrip.com {城市} {酒店名}」拿携程详情页 URL → `search_hotel_reviews(hotel_url_or_id=URL, checkin=入住日, checkout=退房日)`（**带上行程日期**，返回的房型实时价按该日期计；缺省按一周后计，1~3 分钟/家）
3. 爬取结果给用户看：**房型实时价（起价/晚）+ 差评要点 + 实拍图路径**，请用户确认后再定稿——图片是给人看的决策依据，不要爬一堆落选酒店浪费时间和暴露风险
   - 房型价是「起价」口径（部分房型低价促销价），报给用户时说「¥X 起」；比价仍以用户自己在 App 看到的为准
4. **一家酒店只爬一次**（结果在 hotels/ 里，别重复爬）；单次规划最多爬 2~3 家；禁止对所有备选批量爬

解读要点：
- **差评是硬伤探测器**：虫子/卫生/设施故障类差评 → 直接按「评价红线」判死；服务类差评看酒店回复是否敷衍
- **差评占比**：差评数/总评论数 > 3% 且近半年集中 → 降低倾向度
- **好评关键词**与子评分（卫生/环境/服务/设施）验证宣称卖点（宣称亲子 → 看有无「亲子/家庭」关键词）
- 评分门槛 4.7 适用于平台展示分；携程评论页的分数口径不同时以平台页面为准
- 爬取失败（环境未配置/超时）→ 如实告知用户改用 search_web 查口碑，**不阻塞**、不编造评论内容

注意：该工具慢（内置拟人限流：滚动 900ms/轮、图片下载 400ms/张、一家酒店最多 5 张实拍图）。

## 筛选标准

### 评分门槛
- 只看评分 **4.7 及以上**的酒店（满分 5.0）

### 位置策略

| 景点分布 | 出行方式 | 推荐住宿区域 |
|---------|---------|------------|
| 景点集中 | 任意 | 景点集中区域附近 |
| 景点分散 | 自驾/租车 | 市区（餐饮便利、环境好） |
| 景点分散 | 公共交通 | 车站/机场附近商业区（若不偏远）或核心市区（若偏远） |

- 市区具体住哪里，搜索小红书或用 AI 选最方便的位置
- 最方便的位置价格过高时，可适当远一点点

### 品牌优先级

七天快捷 < 锦江之星 < 如家 < 汉庭 < 全季 < 桔子 < 亚朵（从前到后等级递增）

- 主要参考如家、汉庭，根据预算上下调整
- 七天快捷、锦江之星、如家：注意辨别是否只是挂名连锁（查评论+图片+房间布置判断），挂名的降低倾向度
- 连锁酒店优先于非连锁

不要只局限于品牌，也可以搜民宿、其他品牌连锁酒店。

### 加分项

- 开业至今不到 2 年且评价好（但评论有「酒店设施老」字样的按老酒店处理）
- 评价特别多、评分 4.7+、评论真人多、图片多的民宿/酒店
- 离景点特别方便、质量差不多、价格可接受的酒店

### 评价红线

- **有好几个评论特别多虫子** → 直接不要
- **特别多评论说卫生有较大问题** → 直接不要（极个别说卫生问题的可忽略；吹毛求疵对着一点污渍打低分的可忽略）
- **服务态度不好、不让延迟退房** → 忽略
- **评论说酒店特别难找** → 打分降低
- **评论图片跟官方图片一样** → 忽略图片信息
- 民宿可看对房东/老板的评价

## 推荐

- 如果客户有自己的需求（降低/升高标准等），一切按客户要求来
- 阶段3 逐 part 确定：默认给 **1 家主推 + 1 家备选**（给出完整名称）；客户想多比较时给 3~5 个
- **给出酒店完整名称**，不要只有大致名称

## 联动规则（与行程/预算）

- 阶段3：住宿与行程同段给出，客户想换位置 → 当场调整该 part 的行程动线
- 阶段4 卡预算需要降住宿档/换酒店 → **严格按本技能标准重新搜索推荐**，不许随手换、绝不编造
- 上限：每个 part 最多微调1次景点路线，最多固定酒店重跑1次该 part 方案

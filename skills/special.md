# 特殊要求细节

本技能收录行程规划中需要特别注意的细节约束，agent 在各阶段都应参考。

## 全局特殊要求（阶段1一次确认）

- 美食重视程度、忌口/过敏、必吃与不吃项，在阶段1统一询问；路线涉及多个城市时一次完成整体预搜并写入会话记忆。
- 演唱会、演出、赛事、节庆、展览、特定节目等固定活动，在阶段1结合旅行日期、城市、场馆、票务和交通统一查证。
- 这些要求是全程共享约束，不属于某一个 part。阶段3只负责把已确认内容放进合适日期并复核时效，不得逐 part 重复追问。
- 用户中途新增或修改时，更新会话记忆中的“全局特殊要求”，后续所有 part 以最新版本为准。

## 行李处理

part 间转移时（换住宿地/跨一趟大交通 = 换 part，见总则「核心概念：part」），游客不能一直带着行李玩。在阶段1信息采集时必须询问**行李难不难拿**。

### 刚到一个 part（下车后）

| 方案 | 说明 | 对路线的影响 |
|------|------|------------|
| 先回酒店放行李再玩 | 下车后先去酒店放行李，再轻装出去玩 | 酒店位置影响游玩顺序；可能需给 2-3 种路线选少绕路的 |
| 行李寄存车站 | 存车站储物柜或周边寄存商店 | 需搜小红书查「XX站 行李存放」了解方式+费用；站存站取不绕路 |
| 带着行李跑 | 游客说不怕带行李 | 路线最自由，但不推荐 |

### 要离开一个 part（上车前）

| 方案 | 说明 | 对路线的影响 |
|------|------|------------|
| 先回酒店拿行李再去站 | 退房后先玩，玩完回酒店取行李再去车站 | 酒店需在景点和车站之间顺路 |
| 先去车站存行李再玩 | 退房后先去车站存行李，轻装玩完回来取 | 同「寄存车站」，方向是出发时 |
| 退房时寄存酒店前台 | 酒店前台寄存，玩完回来取 | 最方便，但需酒店支持 |

### 行李规划原则
1. 优先少绕路，绕不开跟用户说清楚取舍
2. 酒店位置有多种选择时给 2-3 种路线方案，标明优缺点
3. 寄存费用要说清楚储物柜/寄存商店的大致预算
4. 寄存信息需 search_web 搜小红书/攻略确认，不编造

## 换乘查找

直达火车/动车等待很久时，按优先级尝试：
1. 12306 自带的中转方案
2. 沿途省会、交通枢纽换乘
3. 用地图工具在顺路的站查找换乘方案
4. 都不行则根据稀少班次略微调整旅游方案

## 市内地铁/公交接驳（共享单车规则）

规划市内地铁/公交路线时，必须考虑站口到出发地/目的地的接驳距离：

| 接驳距离 | 处理 |
|----------|------|
| ≤2km | 步行即可，无需特别处理 |
| >2km | **强制建议骑行接驳**：先 search_web 确认该城市有共享单车（如「城市名 共享单车」）。有 → 建议骑行至站口/出站后骑行，方案可用；**没有 → 放弃该换乘方案**，改选直达线路或其他交通方式（打车等） |

地图上换乘路线按**高德最优方案全量绘制**（含步行接驳段），整条线的标记按方案内容自动判定：含地铁/公交线路 → **公共交通**（深蓝）；含打车段 → **打车**（深紫）；仅步行 → **步行/骑行**（深青蓝）。图例只标大类，换乘的具体线路（哪条线、在哪换站）必须在文字方案里说清楚，如：「骑行 1.2km 至五道口站 → 13号线 → 知春路换 10号线 → 东直门站」。

## 天气出行建议

- 查找预报天气，给出合理出行建议（衣物、是否带伞、防晒等）
- 搜索往年同期攻略，给出季节性出行建议

## 特殊约束

- **打车口径查证**：「打车约 X 分钟」「当天往返可行」这类判断必须用 `route_check` 查真实驾车距离/时长，不要拍脑袋估（经验线：散点到区核心 ≤90min 算可当天往返辐射景点；区内最远两点 ≤30min 算「打车方便」）
- **骑行禁用**：用户说不会骑车，全程所有交通推荐中不得出现共享单车/电动车
- **预约提醒**：景点是否需要提前预约必须查清楚并标注
- **信息时效**：车次/票价/门票可能变动，每次提醒「以实际购票/官方信息为准」
- **路线为驾车参考**：地图上的路线是驾车导航路线，公共交通出行的用户需注意说明仅供参考
- **地图生成不阻塞**：地图失败继续输出文字方案

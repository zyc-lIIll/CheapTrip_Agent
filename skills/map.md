## 地图技能

生成行程地图是「拾光者」的核心能力。地图分两种，按阶段调用：

### 何时生成地图

| 阶段 | 生成什么 | 说明 |
|------|---------|------|
| 阶段1（信息采集） | 1 张候选位置关系图（可选） | 用户没定目的地时，候选地 geocode 后调 generate_overview_map（hubs 传空数组、只传 points），只列点展示大致位置关系帮用户选，不画交通 |
| 阶段2（大局规划） | 1 张全程总览图 | part 划分与大方向确认后调 generate_overview_map，展示交通便利区意会圈+辐射景点+大交通连线 |
| 阶段3（逐 part 确定） | 每个 part 各 1 张城市详细图 | 景点确定后调 generate_city_map 展示分布；行程定好按游览顺序连路线 |
| 阶段5（完整攻略） | 重新生成总览图 + 各 part 城市图 | 按最终确定的行程重新调一次，确保地图和方案一致 |

### 阶段3 城市图调用时机

每个 part 独立处理，流程：
1. 搜索该 part（交通便利区辐射范围）的核心景点（10-15 个）
2. 对每个景点调 `geocode` 拿经纬度
3. 调 `generate_city_map`，把**该 part 所有推荐景点**都放进去（routes 留空或按大致游览顺序连），展示给用户
4. 告诉用户「这是 XX part 的景点分布图，你看哪些想去、哪些太远可以去掉」
5. 用户确认后再敲定该 part 的行程与住宿

### geocode —— 地理编码

输入地名，返回经纬度。

```
geocode({"address": "北京"})        → 「北京」→ 经度 116.40，纬度 39.90（北京市）
geocode({"address": "故宫", "city": "北京"})  → 加 city 消歧义
```

### generate_overview_map —— 整体路线总览图（part 化）

白底模式图，两种用法：

**用法一：总览图（part 化，阶段2/阶段5）**——交通便利区画**意会圈**（虚线圆，表示大致范围），偏远辐射景点用细虚线连到区圈边（多归属都画），part 间大交通为彩色条纹线。图例按实际内容裁剪。

```
generate_overview_map({
    "hubs": [
        {"name": "延安市区", "lon": 109.49, "lat": 36.60},
        {"name": "榆林市区", "lon": 109.75, "lat": 38.29}
    ],
    "points": [
        {"name": "宝塔山", "lon": 109.492, "lat": 36.617, "type": "scenic"},
        {"name": "延安站", "lon": 109.51, "lat": 36.61, "type": "station"},
        {"name": "壶口瀑布", "lon": 110.47, "lat": 36.13, "type": "scenic"},
        {"name": "波浪谷", "lon": 108.85, "lat": 37.58, "type": "scenic",
         "hubs": ["延安市区", "榆林市区"]},
        {"name": "榆林榆阳机场", "lon": 109.74, "lat": 38.17, "type": "airport"}
    ],
    "routes": [
        {"from": "延安市区", "to": "榆林市区", "transport": "大巴"}
    ]
})
```

- `hubs`：交通便利区中心（part 核心，geocode 过的市区/县城坐标）。**意会圈半径由工具确定**（区内点最远距离×1.2，下限 4km），无需指定
- `points`：区内点/辐射景点，`type` 决定标记样式：`station`（火车站=方块）、`airport`（机场=叉）、`scenic`（景点=圆点，默认）、`city`（出发地/目的地等普通城市=圆环）
- `points[].hubs`：偏远点的辐射归属（hub 名列表）。多归属点（如波浪谷）传多个，图上都画线；不传则工具按距离自动挂靠（d ≤ 2×最近区距离的都画）
- **标签自动防叠**：相邻点位标签在图上放不下时，工具自动打包成一条概述（如「郑州市区（4 处）」，含 hub 时以 hub 名为概述），marker 照常逐个画保留位置；成员明细写进图例（「郑州市区（4 处）：二七广场、河南博物院、…」）。每个打包组还会自动追加一张**聚焦放大图**（只含组成员+全名标签，命名 `overview_{n}_c{k}.png`，同城市图簇放大图惯例），路径在工具返回里告知用户。无需调用方处理
- `routes`：part 间大交通（含出发地→第一站、末站→返程），`from`/`to` 引用 hubs/points 里的 `name`，`transport` 标交通方式
- 阶段2 与阶段5 各画 1 张（阶段5 按最终确认结果重画）

**用法二：位置关系图（阶段1 候选展示）**——`hubs` 传空数组，只传 `points`（type 用 `city`/`scenic`），`routes` 不传：不画圈、不画交通，只列点展示候选地大致位置关系，帮用户在候选之间做选择。

```
generate_overview_map({
    "hubs": [],
    "points": [
        {"name": "延安", "lon": 109.49, "lat": 36.60, "type": "city"},
        {"name": "榆林", "lon": 109.75, "lat": 38.29, "type": "city"},
        {"name": "壶口瀑布", "lon": 110.47, "lat": 36.13}
    ]
})
```

### generate_city_map —— 城市详细图

高德真实地图底图 + 景点标记 + 底部图例。阶段2展示景点分布时 routes 可留空。

```
// 阶段2：展示景点分布（只标点，不连路线）
generate_city_map({
    "city": "北京",
    "pois": [
        {"name": "天安门", "lon": 116.397, "lat": 39.909},
        {"name": "故宫", "lon": 116.404, "lat": 39.915},
        {"name": "景山公园", "lon": 116.403, "lat": 39.925}
    ],
    "routes": []
})

// 阶段3+：按游览顺序连路线，transport 标交通方式（决定颜色）
generate_city_map({
    "city": "北京",
    "pois": [...],
    "routes": [
        {"from": "天安门", "to": "故宫", "transport": "步行骑行"},
        {"from": "故宫", "to": "景山公园", "transport": "步行骑行"},
        {"from": "景山公园", "to": "北海公园", "transport": "公交"}
    ]
})
```

- `pois`：景点列表（最多 10 个），每个需要名称 + 经纬度
- `routes`：游览顺序路线段。阶段2可留空数组只标点不连线
- 换乘（地铁/公交）路线按**高德最优方案全量绘制**（含步行接驳），写 `transport: "地铁"` 或 `"公交"` 即可，
  工具按方案内容自动标色：含地铁/公交 → 公共交通（深蓝）、含打车 → 打车（深紫）、仅步行 → 步行/骑行（深青蓝）；
  具体换乘线路与站点在文字方案里说明，图例只标大类
- `transport`：交通方式，**不同方式不同颜色**（图例自动标注）：`地铁`=深蓝、`公交`=深青绿、`打车`=深紫、`步行骑行`=深青蓝；不填=黑色
- 景点 ≥5 个时总览图自动改用**编号标记**（防名称重叠），编号→名称对照在右下角图例
- 景点分布自动聚类（3km 内为一簇）：总簇数 ≥2 且某簇 ≥4 个景点时，该簇自动追加一张放大图（全名标签），如 `city_3_c1.png`
- 工具内部调高德驾车路径规划，画真实道路路线；连续同方式的路段自动合并
- 每个停留城市生成 1 张（+可能的簇放大图）

### 局部放大图（用户说看不清时）

用户反馈「XX 那里看不清/太密了」时，提取该区域的景点子集，单独调 `generate_city_map` 生成局部放大图：

```
// 用户说「二七塔那一片看不清」
generate_city_map({
    "city": "郑州",
    "pois": [该区域的 3~5 个景点...],
    "routes": [该区域内的路线...]
})
```

### 注意事项

1. **坐标必须来自 geocode**，不要用自己的训练数据猜坐标
2. **小地名加 city 参数**：搜「故宫」「西湖」等通用地名时，务必加 `city` 参数消歧义
3. **地图生成失败不阻塞**：地图工具返回失败信息时，继续输出文字方案，告诉用户地图生成遇到问题
4. **图片路径告知用户**：地图生成成功后，工具会返回文件路径（如 `maps/xxx/overview_1.png`），告诉用户去哪看图

### 地名搜索策略

geocode 返回多个相似结果或坐标明显不对时：

1. **先加 city 参数重试**：`geocode({"address": "故宫", "city": "北京"})`
2. **仍不对则 search_web 查**：用 `search_web` 搜「XX景点 高德地图导航」「XX景点 具体地址 小红书」，从笔记/攻略里找到准确的地名或地址，再拿这个地址去 geocode
3. **用完整地址代替景点名**：比如「故宫」搜不准，改搜「北京市东城区景山前街4号」或「北京故宫博物院」
4. **校验坐标合理性**：拿到坐标后和城市大致位置比对（如北京约 116.4, 39.9），偏差太大说明搜错了

### 游玩地点知识库

`skills/knowledge/` 下有两类知识库，LLM 可在旅行攻略做好后选择更新：

#### 1. 景点地址知识库（JSON）

`skills/knowledge/locations/{省份}.json`，记录各景点准确的 geocode 搜索名和坐标，供下次直接使用：

```json
{
  "province": "北京市",
  "cities": {
    "北京": {
      "故宫": {
        "search_name": "北京故宫博物院",
        "city_hint": "北京",
        "lon": 116.404,
        "lat": 39.915,
        "note": "直接搜「故宫」可能返回台湾故宫，务必带 city"
      },
      "颐和园": {
        "search_name": "颐和园",
        "city_hint": "北京",
        "lon": 116.268,
        "lat": 39.999
      }
    }
  }
}
```

- 生成地图前先查对应省份的 JSON，有记录直接用坐标，跳过 geocode
- geocode 成功的景点，攻略做完后更新进 JSON（追加新景点、修正旧条目）

#### 2. 旅游攻略知识库（Markdown）

`skills/knowledge/guides/{省份}.md`，记录各城市的游玩攻略要点（仅供参考参考）：

```markdown
# 北京市攻略要点

## 故宫
- 需提前预约，旺季提前7天
- 建议游览时长 3-4 小时
- 从午门进、神武门出，单向

## 颐和园
- 旺季人多，建议早到
- ...
```

- 攻略做完后，如有值得记录的避坑/预约/时长等信息，更新到对应 .md
- 这部分只是参考，不替代实时搜索

#### 使用规则

- 两类知识库均按省份组织，文件不存在时正常走默认流程
- **攻略做好后主动更新**：完成一次旅行规划后，检查是否有新的景点地址或攻略要点值得记录，更新到对应知识库文件
- 知识库目前尚未初始化，首次使用时按上面的地名搜索策略正常走
